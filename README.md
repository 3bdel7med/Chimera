# Chimera 🧬

Describe a feature in plain language. Chimera plans it with **Google Gemini**, generates the files in batches, merges them into your Laravel app through the **PHP AST**, runs the tests it wrote, and lets you undo everything with one command.

> ⚠️ **Development tool only.** Chimera writes PHP files, injects routes and runs migrations. Install it with `--dev`; it refuses to run when `APP_ENV=production`. Review every change before committing.

## How it works

```
 php artisan chimera:morph "A task manager with projects and due dates"
        │
        ▼
 1. Scan        AST summary of your models, controllers, routes, tables (never reads .env)
 2. Conventions how YOUR project writes validation, responses, models, tests (learned from your AST)
 3. Plan        Gemini answers with a BLUEPRINT: the list of files and what each is for (no code yet)
 4. Confirm     you see the plan as a file tree; --dry-run stops here
 5. Generate    files are written in batches (default 4 per AI call). A batch the model truncates is
                split in half automatically; PHP that does not parse is sent back with the error
 6. Audit       generated code is checked against your conventions; violations go back to the AI
                BEFORE anything touches your disk
 7. Apply       a checkpoint is opened, originals are backed up, files are created / modified / injected
 8. Migrate     only the migrations generated by this run
 9. Verify      the generated tests run on SQLite :memory:; failures are fed back to Gemini (self-healing)
10. Trust       deliberate bugs are planted in the generated code to see whether those tests notice
11. Summary     file tree with each file's state, trust score, what to `composer require`, how to roll back
```

## Installation

```bash
composer require --dev abdelhmed/chimera
php artisan vendor:publish --tag=chimera-config     # optional
```

```dotenv
GEMINI_API_KEY=your-key
CHIMERA_GEMINI_MODEL=gemini-2.5-flash               # any Gemini model your key can use
```

Requires PHP 8.1+ and Laravel 10, 11 or 12.

## Commands

| Command | What it does |
|---|---|
| `chimera:morph {prompt?}` | Run the full flow. Options: `--dry-run`, `--yes`, `--no-migrate`, `--no-tests`, `--no-trust`, `--no-conventions` |
| `chimera:learn` | Learn your project's conventions, choose which to keep, save `.chimera/conventions.json` (`--show` only prints, `--yes` saves all) |
| `chimera:history {id?}` | List runs (or the files of one run) |
| `chimera:rollback {id?}` | Roll back the run's migrations, restore modified files, delete created ones (default: latest) |

## Trust Score: do the AI's tests actually test anything?

Green tests are not proof. AI-written tests often pass because they assert very little. After the generated tests pass, Chimera plants **small deliberate bugs** in the generated application code (through the AST) and re-runs the tests for each one. A bug the tests notice is *killed*; a bug nobody notices *survived*. The score is the share killed.

| Deliberate bug | Example |
|---|---|
| comparison flipped | `!==` becomes `===`, `>=` becomes `<` |
| logic flipped | `&&` becomes `\|\|` |
| negation removed | `if (! $task->isOpen())` becomes `if ($task->isOpen())` |
| status code changed | `json($x, 201)` becomes 200, `abort(403)` becomes 404 |
| validation weakened | `'title' => 'required\|string'` becomes `'string'` |
| guard deleted | `$this->authorize(...)`, `abort_if(...)` removed |

Survivors are listed with file, line and what was changed, so you know exactly which test is missing. Notes:

* It only measures code Chimera created or fully rewrote; INJECT fragments, migrations, routes, views and tests are not mutated.
* Some mutants are *equivalent* (the change cannot alter behaviour), so 100% is not always reachable. Treat the score as a guide, not a grade.
* It adds one (fail-fast) test run per bug, capped by `trust.max_mutants` (default 20) and `trust.mutant_timeout`. Disable with `--no-trust` or `trust.enabled`.
* Your files are changed on disk for a moment. The original is restored in a `finally` block and also kept in `storage/chimera/mutation-recovery.json`; if the process is killed mid-run, the next `chimera:morph` restores it first.

## Conventions: code that looks like your code

`php artisan chimera:learn` reads your project through the AST and writes down what it finds, for example:

```text
validation.form-request     Validate input with dedicated Form Request classes; never validate inline in controllers.   (8 of 8 store/update actions)
architecture.services       Put business logic in service classes under app/Services; keep controllers thin.            (4 classes)
php.strict-types            Start every PHP file under app/ with declare(strict_types=1);                               (12 of 12 files)
tests.pest                  Write tests with Pest: it()/test() closures and expect() assertions.                        (3 of 3 test files)
```

* A habit becomes a convention only when it clearly dominates (at least 70% of a meaningful sample); mixed projects get no rule rather than a wrong one.
* The command lets you switch conventions off, and saves `.chimera/conventions.json`. **Commit it**: your team shares the same rules. Add your own by hand with `"source": "custom"`; relearning keeps your choices and custom rules.
* Without the file, Chimera learns on the fly in memory, so the first run already benefits.
* Every convention is shown to the AI in the plan and in every code request. The ones that can be checked mechanically (Form Requests instead of inline validation, no queries in controllers, `strict_types`, return types, Pest vs PHPUnit) are also **verified on the generated code**; violations are sent back to the AI once, with the exact problem and its own code, before any file is written. Anything still wrong is listed in the summary.
* Disable with `--no-conventions` or `conventions.enabled`.

## INJECT: changing files you already own

The model never rewrites your existing classes blindly. For existing PHP files it returns a *skeleton with only the new members*, and Chimera merges it through the AST, keeping your formatting:

* new methods, properties, constants and traits are added; members that already exist are left untouched
* list properties such as `$fillable` get only the missing entries
* `use` imports are merged without duplicates or alias clashes
* route statements are appended to the routes file, skipping any that are already there
* injecting the same snippet twice changes nothing

## Safety

* Paths from the model are validated: only `app/ routes/ database/ resources/ tests/ config/ lang/` are writable; `..`, absolute paths, `.env*`, `vendor/`, `storage/`, `.git/` are always rejected.
* Existing files are never silently overwritten: a `CREATE` on an existing path becomes a visible `MODIFY`, and every touched file is backed up in `storage/chimera/checkpoints/<id>/`.
* If applying fails half-way, the checkpoint is rolled back automatically.
* Migrations run with `--path`, so your own pending migrations are never executed.
* Chimera never edits `.env` or `composer.json`; it tells you what to add.

## Architecture

```
src/
├── Contracts/      LlmClient, ProjectFiles, ProjectScanner, Injector, CheckpointStore, MigrationRunner, TestRunner, Reporter, ProgressTracker, ConventionStore, MutationRecovery
├── Data/           Immutable DTOs: FileSpec, Blueprint, GeneratedFile, ExecutionReport, TestResult, Checkpoint
├── Enums/          FileAction (CREATE/MODIFY/INJECT), FileType (also defines generation order)
├── Analysis/       ClassSummarizer, RouteSummarizer, AstProjectScanner, PhpSyntax (php-parser)
├── Planning/       BlueprintPlanner, BlueprintParser, BlueprintNormalizer, BatchPlanner
├── Generation/     FileGenerator, BatchPromptBuilder, GeneratedFileValidator
├── Injection/      ClassMembersInjector, RouteInjector, ImportMerger, FormatPreservingEditor, InjectorRegistry
├── Application/    ChangeApplier
├── Checkpoint/     FilesystemCheckpointStore, RollbackService
├── Verification/   ProcessTestRunner, HealingService
├── Conventions/    ConventionLearner + 8 AST Detectors, ConventionChecker + 6 Checks, FilesystemConventionStore
├── Trust/          MutantGenerator + 6 Operators, MutationRunner (restores files), TrustAnalyzer, mutation recovery
├── Llm/            GeminiClient (the only class that knows Gemini's REST format)
├── Pipeline/       MorphPipeline + one small Stage per step (Scan, Plan, Confirm, Generate, Apply, Migrate, Verify, Summary)
└── Console/        Thin commands + ConsoleReporter (Laravel Prompts)
```

Patterns: **Pipeline / Chain of Responsibility** (stages), **Strategy / Adapter** (`LlmClient`, `TestRunner`, `CheckpointStore`, `MigrationRunner`), **Registry** (`InjectorRegistry`), **Visitor** via nikic/php-parser, **immutable DTOs**. Everything outside `Llm/`, `Console/`, `Migration/` and `ChimeraServiceProvider` is framework-agnostic and unit-tested with fakes.

## Customising

* **Prompts**: `php artisan vendor:publish --tag=chimera-prompts` copies `blueprint.system.stub`, `generate.system.stub` and `heal.system.stub` to `stubs/chimera/`. Edit them to enforce your house style (e.g. "always use Actions, never Services").
* **Another model**: implement `Abdelhmed\Chimera\Contracts\LlmClient` (one method) and bind it in your own service provider.
* **Another checkpoint strategy** (e.g. git commits): implement `CheckpointStore`.
* **Bigger / smaller batches**: `generation.files_per_batch`. Lower it if your model has a small output limit.

## Known limits

* Conventions are statistical: a habit seen in too few files is ignored, and a learned rule can be wrong for new code. Review `.chimera/conventions.json` once.
* Trust scoring measures the generated tests against six kinds of bugs, not every possible bug.

* Route summaries do not resolve `Route::group` prefixes.
* Healing only fixes files the model can see in the test output; failures caused by missing packages or `.env` values need your help.
* If `routes/api.php` does not exist (Laravel 11+), Chimera creates it but warns you to register it (`php artisan install:api`).
